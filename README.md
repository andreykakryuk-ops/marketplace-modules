# Marketplace Modules — готовые модули для сайтов продавцов

Готовый самостоятельный модуль на Next.js/React, выделенный из рабочего складского проекта. Его можно запустить отдельно либо дать Cursor вместе с кодом своего сайта для интеграции. Внутри нет склада владельца, его заказов, аккаунтов, API-ключей или истории Git.

Публичный репозиторий: https://github.com/andreykakryuk-ops/marketplace-modules. Код доступен всем без приглашений; можно скачать ZIP, клонировать или сделать Fork в свой аккаунт GitHub. Сейчас включён складской модуль с четырьмя разделами. Позже сюда можно добавлять другие самостоятельные модули и технические задания.

```sh
git clone https://github.com/andreykakryuk-ops/marketplace-modules.git
cd marketplace-modules
```

Откройте папку в Cursor и передайте ему текст из CURSOR_PROMPT.md вместе с исходниками своего сайта. Лицензия [MIT](LICENSE) разрешает использовать и изменять этот код, в том числе в коммерческом сайте, с сохранением уведомления об авторстве и лицензии. Правила добавления модулей — [CONTRIBUTING.md](CONTRIBUTING.md).

**Начните с [START_HERE.md](START_HERE.md).** Для Cursor — [CURSOR_PROMPT.md](CURSOR_PROMPT.md). Пошаговая настройка и контрольный пример — [ONBOARDING.md](ONBOARDING.md). Разработчику — [INTEGRATION.md](INTEGRATION.md).

Включено:
- Склад компонентов и готовых товаров, количества, резерв, средневзвешенная себестоимость, личный порядок/скрытие строк.
- Партии прихода с ценой закупки, пересчётом стоимости и журналом движений.
- Комплекты: состав и количество каждого компонента, расчёт потребности и себестоимости.
- Ручные поставки/сборки, автоматические FBS WB/Ozon, опционально WB FBW/FBO; защита от повторного списания и обработка отмен/разделения заказов.
- Собственные подключения API, связи артикулов с комплектами, вход и права сотрудников.

API интеграции читают существующие заказы/поставки. Подтверждение заказов и отправка в маркетплейс остаются в кабинете продавца; нажатие «Провести» здесь выполняет **локальную складскую операцию**. Это не обещание автоматической внешней отгрузки или печати этикеток.

## Запуск

Нужны Node.js 22.10+ и npm, постоянный каталог данных и один процесс Node.

```sh
npm ci
# Скопируйте .env.example в .env.local
npm run dev
```

Откройте http://127.0.0.1:3100/setup и создайте свой вход владельца. Первичная база пустая; общих паролей нет. Затем следуйте ONBOARDING.md.

```sh
npm run check
npm run build
npm start
```

В production нужны HTTPS, постоянный writable volume `data/` и один процесс/реплика. Обычный serverless без постоянного диска не подходит для файловой базы и фонового таймера. Для нескольких реплик перенесите хранение и синхронизацию в БД/отдельный worker по INTEGRATION.md.

## Границы пакета

Финансы, реклама, RNP и личные данные исходного владельца не включены. Поддерживается один кабинет WB и один Ozon в одной установке; ключ другого продавца поверх действующей привязки отклоняется.

Дополнительные столбцы закупок («в пути», «заказано») и калькулятор покрытия сохранены. **Историю продаж и остатки маркетплейсов для прогноза нужно подключить через адаптер `demand-input.json`** из INTEGRATION.md. Автоматический FBS импорт уже включён и от этого адаптера не зависит. Без подтверждённого спроса дни покрытия остаются прочерками.

Версии зависимостей закреплены в package-lock.json. Реальные ключи получателя здесь не проверялись: подключение нужно пройти в его кабинете. Результат проверок пакета записан в VALIDATION.md.
