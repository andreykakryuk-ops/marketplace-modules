# Добавление задач и модулей

Сейчас в корне находится самостоятельное приложение «Склад / Поставки / Приход / Комплекты». Новые независимые модули размещайте в `modules/<имя>/`; не подменяйте существующее приложение новым проектом. Общий каталог модулей и ссылки обновляйте в README.md. Связанные улучшения складского модуля остаются в текущих app/, components/ и lib/.

Для задачи создайте GitHub Issue: цель, сценарий пользователя, границы, критерии готовности, необходимые интеграции. Для кода — отдельная ветка и Pull Request с описанием результата и фактических проверок. Форма задачи находится в .github/ISSUE_TEMPLATE/task.md. Публикуйте только технический контекст, не личную переписку, закрытые обсуждения или финансовые данные.

У каждого нового модуля должны быть инструкция запуска, зависимости, пример без реальных данных, описание подключения своих API, ограничения и проверки. Не добавляйте ключи, cookies, runtime data, .env.local, рабочие остатки, реальные заказы или пользовательские данные. Предлагайте свои изменения только под лицензией этого репозитория и сохраняйте сведения о лицензиях стороннего кода.

Проверки складского модуля: `npm ci`, `npm run check`, `npm run build`, `node scripts/check-package.mjs`. Сценарий ручной проверки — ONBOARDING.md. Используйте отдельную тестовую установку; синтетический seed нельзя запускать поверх рабочего склада. Ключи вводятся в настройки своей установки, не в Issues и не в Cursor.

Открытый репозиторий предоставляет код для внедрения. Развёртывание на рабочем сайте выполняется отдельно с согласия его владельца после проверки результата.
