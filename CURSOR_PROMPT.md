# Задание для Cursor — скопируйте текст ниже

Мне нужно внедрить в мой существующий сайт готовый модуль из этой папки: **Склад, Поставки, Приход, Комплекты**. Изучи README.md, ONBOARDING.md и INTEGRATION.md, затем исходники этого пакета и моего сайта. Не замени существующую главную страницу и не переписывай сайт целиком.

1. Определи стек, маршрутизацию, авторизацию, модель пользователей, БД и способ запуска фоновых задач. Предложи наиболее простой совместимый способ: встроенные маршруты, отдельное приложение/поддомен или адаптация доменной логики к backend моего сайта. Если существенного доступа не хватает, укажи его и продолжай независимую подготовку.
2. Сохрани все складские правила пакета: компоненты и готовые комплекты, составы BOM, средневзвешенная стоимость прихода, резерв FBS, готовые остатки, запрет нехватки, документы движений, обработанные ID и однократное списание. Не выдумывай начальные остатки/цену/связи товаров. Мой склад начинается пустым.
3. Используй мою авторизацию и серверные права. API и управление пользователями — владельцу. Личный порядок/скрытие строк — каждому сотруднику. Защити все мутации на сервере. Не выключай защиту ради работоспособности.
4. Сделай отдельный экран настроек для МОИХ ключей: единый WB и Ozon Seller Client ID + ключ. Они остаются на сервере, не попадают в frontend, Git, логи или этот чат. Performance для складских разделов не нужен. Не используй кабинеты/адреса/данные исходного автора.
5. Сохрани автоматический импорт существующих FBS WB/Ozon, восстановление пропущенных заказов, проверки пагинации и составов, отмены, разделение партий и маркеры повторной обработки. При нескольких процессах нужны общий mutex, БД-транзакции и один worker; файловая база пакета рассчитана на один процесс и постоянный диск. Не добавляй внешнее подтверждение/отгрузку заказов без отдельной задачи.
6. Обеспечь точные связи артикулов площадок с готовыми товарами, включая несколько артикулов одного физического товара; неизвестный артикул должен требовать настройки. Предложи мне ввести компоненты, количества, закупочные цены и составы комплектов. Не выбирай соответствия сам по похожему названию.
7. Если мне нужны столбцы прогноза закупок, реализуй адаптер спроса из INTEGRATION.md по МОИМ полным заказам и остаткам. Не считай расход из одного текущего списка новых FBS-заказов. Без подтверждённого источника оставь «неизвестно», а не 0.
8. Запусти проверки пакета и интеграции. На синтетических данных проверь полный пример из ONBOARDING: приход → комплект → сборка → отгрузка → повторный sync → отмена, нехватку, сохранение после рестарта и права сотрудников. API моего кабинета проверяй обычной настройкой; не создавай фиктивные рабочие заказы для теста.
9. Дай мне короткую инструкцию с фактическими адресами страниц, командами, куда ввести ключи, где заполнить склад/составы и как проверить поставки. Сообщи, что реально применено и проверено, что требует моих данных. Деплой на мой рабочий сайт выполняй после подготовки проверенного результата и моего разрешения.

Начни с определения стека моего сайта и карты интеграции. Затем реализуй всё необходимое в согласованных границах до рабочего результата, а не только опиши план.
